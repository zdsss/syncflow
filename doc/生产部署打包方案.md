# SyncFlow 生产部署打包方案

## 设计目标

将 SyncFlow（Next.js 前端 + Spring Boot 后端）部署到 **2GB 内存** 的轻量服务器。

## 架构决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 部署形态 | 双进程（Next.js + Fat JAR） | Next.js 需要独立 Node 进程支持 SSR |
| 反向代理 | Nginx → Next.js(:3000) → Spring Boot(:8088) | Next.js API Routes 负责代理后端 |
| 缓存 | `spring.cache.type=simple` | 用 ConcurrentMap 替代 Redis，省 ~100MB |
| 数据库 | PostgreSQL 裸机安装 | 不用 Docker，PG 调优到 64MB shared_buffers |
| 文件存储 | MinIO 裸机安装 | Go 二进制仅占 ~128MB |
| GC 策略 | SerialGC | 小堆（<512MB）下吞吐最优 |

## 2GB 内存分布

```
PostgreSQL:  ~150MB  (shared_buffers=64MB, max_connections=5)
MinIO:       ~128MB  (Go 二进制)
Java JVM:    ~512MB  (heap 128-384m + metaspace 128m + overhead)
Node.js:     ~200MB  (Next.js SSR)
OS:          ~200MB  (Ubuntu Server 22.04/24.04)
-------------------------------------------
合计:        ~1.19GB, 剩余 ~810MB buffer
```

## 项目文件说明

```
scripts/
├── build.sh              # 本地构建脚本
├── server-setup.sh       # 服务器一次性初始化
├── start.sh              # 启动 SyncFlow（前端 + 后端）
├── stop.sh               # 停止 SyncFlow
├── nginx-syncflow.conf   # Nginx 配置
├── syncflow.service      # systemd 服务
├── syncflow-logrotate    # 日志轮转
├── minio.bin             # MinIO 二进制
└── env                   # 环境变量模板
```

## 构建流程

### 1. 本地构建

```bash
bash scripts/build.sh

# 产物位于 build-artifacts/syncflow-YYYYMMDD-HHMM.tar.gz
```

构建步骤：
1. `pnpm build` — Next.js 生产构建（frontend-next/）
2. `mvn clean package -DskipTests` — 打出 Fat JAR
3. 将前端 .next + node_modules + 后端 JAR + 脚本打包为 `.tar.gz`

### 2. 上传到服务器

```bash
scp build-artifacts/syncflow-*.tar.gz user@your-server:/opt/syncflow/
ssh user@your-server
cd /opt/syncflow
tar xzf syncflow-*.tar.gz
```

### 3. 首次服务器初始化

```bash
sudo bash server-setup.sh
```

该脚本会：
- 安装 OpenJDK 21、Node.js 20、PostgreSQL 16、nginx、MinIO
- 创建 `syncflow` 系统用户和应用目录
- 调优 PostgreSQL 配置（小内存优化）
- 创建数据库和用户
- 配置 MinIO systemd 服务并启动
- 配置防火墙（开放 22、80）

### 4. 配置环境变量

```bash
vim /opt/syncflow/env
```

必须修改的变量：
- `JWT_SECRET` — 至少 256 位的随机字符串

可按需修改的变量：
- `DB_URL` / `DB_USER` / `DB_PASS` — 数据库连接
- `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` — 对象存储凭证
- `SERVER_PORT` — 后端端口（默认 8088）

### 5. 启动/停止

```bash
bash start.sh                   # 启动（前端 :3000 + 后端 :8088）
bash stop.sh                    # 停止
tail -f /opt/syncflow/logs/backend.log   # 后端日志
tail -f /opt/syncflow/logs/frontend.log  # 前端日志
```

访问 `http://<server-ip>`（Nginx :80 → Next.js :3000）。

## 生产配置要点

### Redis 移除

`application-prod.yml` 中：

```yaml
spring:
  cache:
    type: simple
  autoconfigure:
    exclude:
      - RedisAutoConfiguration
      - RedisRepositoriesAutoConfiguration
```

### 数据库连接池

```yaml
spring:
  datasource:
    hikari:
      minimum-idle: 2
      maximum-pool-size: 5
```

### JVM 参数

```bash
-Xms128m -Xmx384m -XX:+UseSerialGC -XX:MaxMetaspaceSize=128m
```

## 更新部署

```bash
# 本地重新构建
bash scripts/build.sh

# 上传并替换
scp build-artifacts/syncflow-*.tar.gz user@server:/opt/syncflow/
ssh user@server
cd /opt/syncflow
bash stop.sh
tar xzf syncflow-*.tar.gz
bash start.sh
```
